## 공통

- 사진 저장(체크인·아웃): DB vs 서버 폴더 vs MinIO -> **DB 저장 유지**. 저장은 포트·어댑터(인터페이스) 뒤에 두어, 사용자가 늘어 DB가 커지면 MinIO로 바로 옮길 수 있게 함
- 사진 보관 기간: 30일 vs 7일 -> 아직 안 정해짐 (7일 검토. 신고는 보통 다음 사람이 하니 일주일이면 충분하다는 의견. 신고 증거 사진은 따로 남길지 같이 정하기)
- 사진 용량: 학교 nginx 업로드 한도 올리기 vs 화면에서 사진 줄여 보내기 -> 둘 다 진행 (줄여 보내기가 기본, nginx 한도는 재웅 확인)
- 장치 토큰: 방(키패드)마다 따로 vs 하나 -> **2번 방 키패드용 토큰 추가**. 환경(로컬·개발·시연)마다 다른 값, DM으로만 전달
- 조도 센서 활용: 사람 없는데 불이 30분 넘게 켜져 있으면 관리자 알림 -> 아직 안 정해짐 (요구사항에 있는지 확인)
- 예약 화면: 방 누르면 예약 vs 즉시 시작 -> **즉시 시작을 기본값**으로 (버튼 따로 안 만들어 화면 단순하게). 로컬에서 시험 후 반영
- 예약 성공 효과: 없음 vs 폭죽 -> **폭죽** (이벤트 당첨된 느낌)
- 시연 서버: **오늘 main 배포** (https://mspace.java21.net, 8414). 완성된 기능만 올리고, 이후 개발은 계속 dev에서
- 알림 읽음 표시 API: 없음 -> **만들기** (지영, 오늘)
- 시간표 가져오기: 에브리타임 API 긁기 vs 캡처 읽기 -> **캡처 읽기** (에브리타임 무단 수집은 이용 정지 위험)
- 발표 때 인터넷: 학교 와이파이 vs 핫스팟 -> **핫스팟** (가장 안전)
